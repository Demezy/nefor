# Artifacts

An entry program returns exactly one `Artifact`:

```lisp
(artifact {:title "Compilation result"
   :findings ["one" "two"]})
```

`artifact` accepts any serializable value and preserves exactly that value in
`CompilationResult.artifact`. MAG adds no fields and assigns no format or
schema to the artifact. Applications define those decisions with ordinary MAG
types. For example, an application that wants a tagged envelope can define and
construct one itself:

```lisp
(type ReportEnvelope {:format String :data {:findings (List String)}})

(artifact
  (as ReportEnvelope
    {:format "example.report/v1"
     :data {:findings ["one" "two"]}}))
```

Artifact extraction and generic serialization are the final steps of MAG
compilation. The consumer owns interpretation and validation of the resulting
JSON structure.

The CLI and Rust `compile` APIs return the same transport value. File-backed
`load` APIs retain it as `LoadedProgram.result` alongside the resident
environment:

```json
{
  "metadata": { "version": 1, "hash": "..." },
  "artifact": {
    "format": "example.report/v1",
    "data": { "findings": ["one", "two"] }
  }
}
```

`metadata` belongs to compilation; `artifact` belongs to the MAG program. A
failure is an error rather than another result variant, so there is no `ok`
field or failure envelope.
