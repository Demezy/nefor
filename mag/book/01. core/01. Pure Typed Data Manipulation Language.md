# Pure Typed Data Manipulation Language

A MAG source file contains expressions. Evaluation is eager, lexical, and
pure: an expression produces a value without mutating an earlier value or
performing the work that value may describe.

Every entry program ends in an `Artifact`, which marks the value the compiler
returns:

```lisp
(artifact {:message "Hello from MAG"})
```

The argument can be any serializable MAG value. Compiling this program writes
that value verbatim as the successful result:

```json
{ "message": "Hello from MAG" }
```

MAG adds no fields or application schema to the artifact. Nothing interprets
the message during evaluation: the compiler verifies and serializes the value,
then stops.

## Bind intermediate values

`let` introduces one immutable name in its containing source-file or
function-body block. Kebab case is conventional, but it is only a convention.
An unquoted name starts with an ASCII letter or one of `_ ? ! * = < >`; the
remaining characters may additionally contain ASCII digits, `-`, `/`, or `.`.
`-` can itself begin a name unless the following characters make a negative
number or the `->` token. The lexer also recognizes the standalone symbol
tokens `+`, `|`, `:`, and `->`. None of `?`, `!`, `*`, `=`, `<`, or `>` has
special behavior inside a name.

```lisp
(let language "MAG")
(let numbers [1 2 3])
(let double
  (fn [[value Int]] -> Int
    (* value 2)))
(let =>
  (fn [[value Int]] -> String
    (str value)))
(artifact {:language language :numbers numbers})
```

Here `=>` is simply the name of a function and `(=> 42)` calls it.

The four bindings above belong to one source-file block. `language`, `numbers`,
`double`, and `=>` remain available to every expression in that block. The last
expression is the block's result; in an entry program it must be an `Artifact`.
A function body follows the same rule, except its last expression is the
function's return value.

Bindings are immutable. Naming a value once and reusing it later does not
create an assignment channel or hidden state. All bindings in a block are
peers: MAG allocates the complete block before evaluating its initializers.
Consequently a value may refer forward to another value, and functions may
recurse through a chain of any length. For example, this strict value resolves
`prefix` from a later peer binding:

```lisp
(let message (str prefix " world"))
(let prefix "hello")
```

Mutually recursive functions use the same peer visibility:

```lisp
(let finished "done")
(let first
  (fn [[items (List Int)]] -> String
    (if (= (count items) 0)
      finished
      (second (remove-at items 0)))))
(let second
  (fn [[items (List Int)]] -> String
    (if (= (count items) 0)
      finished
      (first (remove-at items 0)))))
```

Recursion happens when a function is called, so ordinary call-depth and
evaluation-step limits bound it. Strict initializers, by contrast, must finish
while the block is being constructed. `(let x (str y "!"))` together with
`(let y (str x "?"))` is rejected as the initialization cycle
`x -> y -> x`. A cycle through a call is rejected too: a strict value cannot
call a function that immediately needs that still-initializing value.

## Values and collections

Ordinary strings use escapes such as `\n`, `\t`, `\\`, and `\"`.
Triple-quoted strings are raw and may span several lines. Scala-style
`strip-margin` lets source indentation remain readable without becoming part
of the value:

```lisp
(let script
  (strip-margin """|set -e
                    |echo 'export PATH="$HOME/.local/bin:$PATH"'
                    |find . \( -name '*.mag' -o -name '*.md' \)"""))
(let one-line (replace script "\n" " "))
```

The first value retains its line breaks; the second replaces them with spaces.
Triple-quoted strings perform no interpolation or escape processing.

```lisp
(let record
  {:unit nil                                      ;; Unit
   :bool true                                     ;; Bool
   :int 3                                         ;; Int
   :float 3.5                                     ;; Float
   :string "MAG"                                  ;; String
   :list [1 2 3]                                  ;; List Int
   :map (as (Map String Int) {:one 1 :two 2})})   ;; Map String Int
(artifact record)
```

Records have fixed fields. Lists have one item type, and maps have one key type
and one value type.

### Deriving new values

Records and collections are transformed into new values. `get` reads one
field; `assoc` returns a record with one field replaced and leaves the original
record unchanged:

```lisp
(let record {:name "MAG" :stable true})
(let name (get record "name"))
(let renamed (assoc record "name" "Meta-Algebraic Grammar"))
;; name is "MAG"
;; renamed is {:name "Meta-Algebraic Grammar" :stable true}
```

The basic list operations inspect or reshape a list:

```lisp
(let numbers [1 2 3])
(let joined (concat numbers [4 5]))       ;; [1 2 3 4 5]
(let size (count numbers))                ;; 3
(let head (first numbers))                ;; 1
(let shortened (remove-at numbers 1))     ;; [1 3]
```

Collection indices are known while MAG evaluates the program. Therefore
`(remove-at numbers 1000)` fails compilation with an out-of-bounds evaluation
error rather than creating an invalid artifact.

Higher-order operations accept typed functions. Their result types follow
from the function signature:

```lisp
(let rendered
  (map (fn [[value Int]] -> String (str value)) numbers))
(let selected
  (filter (fn [[value Int]] -> Bool (= value 2)) numbers))
(let repeated
  (flat-map (fn [[value Int]] -> (List Int) [value value]) numbers))
;; rendered is ["1" "2" "3"]
;; selected is [2]
;; repeated is [1 1 2 2 3 3]
```

`indexed-map` also provides each element's position:

```lisp
(let indexed
  (indexed-map
    (fn [[index Int] [value Int]] -> {:index Int :value Int}
      {:index index :value value})
    numbers))
```

`fold` carries an explicitly typed accumulator, while `sort-by` derives a key
for every item:

```lisp
(let copied
  (fold
    (fn [[out (List Int)] [value Int]] -> (List Int)
      (concat out [value]))
    (as (List Int) [])
    numbers))
(let ordered
  (sort-by (fn [[value Int]] -> String (str value)) [3 1 2]))
```

`group-by` derives one string key per item and accumulates duplicate keys into
ordered buckets:

```lisp
(let grouped
  (group-by
    (fn [[item {:group String :value Int}]] -> String (get item "group"))
    [{:group "b" :value 1}
     {:group "a" :value 2}
     {:group "b" :value 3}]))
;; grouped is
;; {"a" [{:group "a" :value 2}]
;;  "b" [{:group "b" :value 1} {:group "b" :value 3}]}
```

The callback runs once per item from left to right. Bucket values retain source
order, while the resulting immutable map exposes its string keys in lexical
order. An empty explicitly typed list produces an empty map.

Map and record keys are available as data as well:

```lisp
(let fields (keys record))
```

### Structural sharing

Compound values are structurally shared. Binding, passing, and storing the same
list, map, or typed value keeps a reference to immutable data instead of
copying the entire structure. This is an evaluator property, not a reference
operation visible to MAG code.

The complete
[`01-values.mag`](../../examples/01-values.mag)
program applies these forms in one artifact.

## Compile without running

The standalone compiler prints the artifact itself as JSON:

```sh
mag compile 01-values.mag --source-dir .
```

```json
{ "record": { "...": "..." }, "copied": [1, 2, 3] }
```

A failed compilation writes a structured diagnostic to stderr, exits nonzero,
and produces no result on stdout. Neither the CLI nor the Rust API executes the
work described by the artifact.
