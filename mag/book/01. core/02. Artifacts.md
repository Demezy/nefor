# Artifacts

An entry program returns exactly one `Artifact`:

```lisp
(artifact {:title "Compilation result"
   :findings ["one" "two"]})
```

`artifact` accepts any serializable value and preserves exactly that value as
the compiler's successful output. MAG adds no fields and assigns no format or
schema to the artifact. Applications define those decisions with ordinary MAG
types. For example, an application that wants a tagged envelope can define and
construct one itself:

```lisp
(type ReportEnvelope {:format String :data {:findings (List String)}})

(artifact
  (as ReportEnvelope
    {:format "example.report/v1"
     :data {:findings ["one" "two"]}}))
```

Artifact extraction and generic serialization are the final steps of MAG
compilation. The consumer owns interpretation and validation of the resulting
JSON structure. The CLI writes that structure directly:

```json
{
  "format": "example.report/v1",
  "data": { "findings": ["one", "two"] }
}
```

The Rust compile APIs return the same JSON value. Compilation retains no
evaluator environment or callable function handle. A failure is an error rather
than another result variant, so success has no compiler-owned envelope and
failure produces no artifact value.
