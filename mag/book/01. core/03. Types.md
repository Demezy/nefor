# Types

MAG checks every program before producing its artifact. Function parameters,
returns, collection items, record fields, and artifact data all participate in
the same type system.

## Nominal records

`type` gives a name to a shape:

```lisp
(type Score {:name String :accepted Bool})
```

Named types are nominal. Record literals are closed anonymous construction
values; a structurally identical literal becomes a `Score` only through explicit
refinement:

```lisp
(as Score {:name "example" :accepted true})
```

Records are closed: every declared field is required and extra fields are
rejected.

## Algebraic data types and tuples

A nominal algebraic data type describes one of several alternatives:

```lisp
(type Accepted {:score Score})
(type Rejected {:score Score :reason String})
(type Decision (adt [Accepted Accepted] [Rejected Rejected]))
```

An anonymous product is an ordered tuple. Order, arity, repetition, and grouping
are preserved:

```lisp
(+ String Int)
```

ADTs and products are data constructors rather than control flow. A program
constructs an ADT case with `construct`:

```lisp
(let decision
  (construct Decision Accepted
    (as Accepted {:score (as Score {:name "review" :accepted true})})))
```

`match` consumes the sum without duplicating its constructor as a string field:

```lisp
(let explanation
  (match decision
    [Accepted accepted (get (get accepted "score") "name")]
    [Rejected rejected (get rejected "reason")]))
```

Every arm has the form `[Constructor binding expression]`. The binding has the
concrete constructor type inside that arm, so `accepted` above is `Accepted`,
not the broader `Decision`. Arms must cover every constructor exactly once and
return one compatible type. The checker rejects a missing, repeated, or
foreign constructor; evaluation selects from constructor evidence already
retained by MAG rather than inspecting serialized data.

## Generic types

Types can declare parameters:

```lisp
(type Box [T] {:value T})
(type Entry [K V] {:key K :value V})
```

`Box String` and `Box Int` retain the same reusable shape with different item
types. `Entry String Int` substitutes `String` for `K` and `Int` for `V` in the
same two-parameter shape. Generic functions can quantify over the same
parameters.

Generic sum constructors use the same type-application syntax in a pattern:

```lisp
(type Some [T] {:value T})
(type None {})
(type Option [T] (adt [Some T] [None Unit]))

(let render-option
  (fn [[option (Option Int)]] -> String
    (match option
      [(Some Int) present (str (get present "value"))]
      [None absent "none"])))
```

Named aliases of `Option Int` preserve the same exhaustive constructors.

[`03-functions.mag`](../../examples/03-functions.mag)

## Type evidence

```lisp
(type Finding {:path String :line Int})

(let tag (type-tag Finding))
(let descriptor (type-evidence tag))
(artifact {:descriptor descriptor
           :identity (type-id descriptor)
           :schema (type-schema tag)})
```

`type-tag` can only name a type known to the checker. Its runtime value has
static type `(TypeTag Finding)`: it is an opaque checked witness, although it
serializes as the semantic descriptor shown below. `type-evidence` projects
that witness to a `TypeDescriptor`. `type-id` converts a descriptor to a
`SemanticTypeId`, serialized as a stable SHA-256 string. `type-schema` converts
a tag to a versioned `TypeSchema` value suitable for validating external JSON.
Ordinary maps cannot forge any of these opaque runtime values.

The artifact above contains these concrete JSON values:

```json
{
  "descriptor": {
    "kind": "named",
    "name": "main.Finding",
    "arguments": [],
    "body": {
      "kind": "record",
      "fields": [
        { "name": "line", "type": { "kind": "primitive", "name": "Int" } },
        { "name": "path", "type": { "kind": "primitive", "name": "String" } }
      ]
    }
  },
  "identity": "sha256:d1977612237ccdf95324ec9147313f3208602d08c151bc1ba765312288fdf4d7",
  "schema": {
    "version": 1,
    "root": {
      "kind": "named",
      "name": "main.Finding",
      "body": {
        "kind": "record",
        "fields": [
          { "name": "line", "schema": { "kind": "int" } },
          { "name": "path", "schema": { "kind": "string" } }
        ]
      }
    }
  }
}
```

The identity is the stable hash of this semantic descriptor. Qualifying the
type under another module name changes both the descriptor name and its
identity. A tag and descriptor serialize to the same JSON descriptor today,
but their runtime types remain distinct: functions expecting a `TypeTag`
cannot be passed a `TypeDescriptor`, or vice versa.
