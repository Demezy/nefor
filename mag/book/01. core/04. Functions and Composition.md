# Functions and Composition

Functions have explicit parameter and return types:

```mag
(|value| => str(value)): fn(Int) -> String
```

They are first-class values. A function can be bound, passed to a collection
operation, called from another function, or returned as part of a larger value.
A complete type on a `let` binding supplies the parameter and result types to
its lambda:

```mag
type Label {name: String, value: Int}
let label: fn(String, Int) -> Label = |name, value| => Label {name: name, value: value}
label("answer", 42)
```

A lambda with more than one parameter has an n-ary `fn(...)` type and is called
with comma-separated arguments. Curried functions instead use arrow types and
nested lambdas, such as `String -> String -> String` and
`|left| => |right| => left`.

## Generic functions

Type parameters appear on the binding before its type annotation:

```mag
type Entry<Key, Value> {key: Key, value: Value}

let entry<Key, Value>: fn(Key, Value) -> Entry<Key, Value> = |key, value| => Entry<Key, Value> {key: key, value: value}

entry("answer", 42)
```

Both type parameters are inferred independently, so the final call returns
`Entry<String, Int>`. Ordinary function calls do not accept explicit term type
arguments; write `entry("answer", 42)`, not `entry<String, Int>("answer", 42)`.
Unlike a generic wrapper that merely preserves one value,
this type captures the reusable relationship between a key and its value.

## Build new vocabulary

Functions are the main composition mechanism in MAG. If a recurring structure
can be expressed as data, a function can construct it and return it under a
smaller interface.

This scales from a helper returning one record to a function returning an
entire domain object. A host library might define configuration plans, UI
trees, or graph nodes; to MAG, all remain ordinary immutable values.

Names containing punctuation are enclosed in backticks. The complete
[`03-functions.mag`](../../examples/03-functions.mag) example combines generic
construction, local functions, and the `` `indexed-map` `` built-in.

## Pure calls can be reused

Completed calls are memoized by function and shared argument values within one
compilation. By default the cache holds 16,384 calls; reaching the limit clears
cached results, so the next identical call evaluates the function body again
and produces the same value. Setting `memoized_calls` to zero disables
memoization.

All evaluator resource limits are compiler options. Their defaults are
1,000,000 evaluation steps, 64 nested function calls, 128 nested expressions,
and 16,384 memoized calls. Rust callers override them through
`CompilerOptions.limits`; the CLI exposes `--evaluation-step-limit`,
`--call-depth-limit`, `--expression-depth-limit`, and
`--memoized-call-limit`. These bounds change compilation cost and failure, not
the meaning of a successfully produced artifact.
