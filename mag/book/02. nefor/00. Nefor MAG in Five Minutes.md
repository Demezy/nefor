# Nefor MAG in Five Minutes

This guide assumes [MAG in Five Minutes](<../01. core/00. MAG in Five Minutes.md>).
MAG supplies typed immutable data, ordinary functions, nominal algebraic data
types, and one artifact value. Nefor's libraries use those mechanisms to build
nodes, agents, deterministic commands, worktrees, products, fixed parallel
work, and runtime-sized consumers. None introduces graph-specific syntax.

> **Scope:** This guide teaches MAG and Nefor library composition only; prompts, task decomposition, review policy, permissions, and domain practice are intentionally simplified and are not prescriptions.

The smallest complete program imports the facade, constructs one root-capable
node, and closes it directly:

```mag
import nefor

compile_graph(script("hello", ShellScriptParams {
  script: "printf 'hello\\n'",
  cwd: ".",
  timeout: timeout_ms(30000),
}))
```

`script(...)` has type `Node<Unit, ProcessResult>`. Constructing it runs
nothing; `compile_graph` adds the output boundary, validates the graph, and
returns its immutable artifact. At runtime an exposed, unfed `Unit` input gets
one activation, while a fed node waits for its dependency.

The next program grows that root into a typed development workflow, then adds
runtime-sized follow-up work. Its imports make the public authoring surface
visible: the Nefor facade is open, configuration-owned agents stay qualified,
and only the colliding facade `Approved` type is suppressed. Suppression removes
that bare import's automatic short spelling, not qualified access to
`nefor.Approved`; it cannot cancel an explicit positive selector. Visibility is
computed as automatic opens minus suppressions plus positive selectors,
independently of declaration order. Use short names for opened library APIs
and qualified names for the configuration-owned `agents` namespace.

```mag
import agents.{}
import core.types.{Either, Result}
import nefor
import nefor.{Approved as _}

// Agents should speak in application types, not generic text envelopes.
newtype LineNumber = Int
type ReviewComment {path: String, line: LineNumber, body: String}
type Review {summary: String, comments: List<ReviewComment>}
type Implementation {summary: String}
type Approved {review: Review}
type NeedChanges {review: Review}
type Followup {title: String, instructions: String}
type Finding {title: String, finding: String}
type FinalSummary {summary: String}

type DevelopmentConfig {
  repository: String,
  worktree: String,
  branch: String,
  base: String,
  build: String
}

// IDs are opaque actor identities; reusable behavior stays in config. Mapping
// one config over IDs produces same-shaped nodes, and sequence sends one shared
// Task to every node and returns results in ID-list order.
let reviewer_config = agents.AgentConfig {
  model: agents.standard,
  system: "Review the task and return concrete ReviewComment values with repository-relative path, source line, and actionable body.",
  tools: read_only_tools,
  tool_approval_policy: no_tool_approval_policy(),
  max_corrections: 2
}
let review_ids = ["security-review", "test-review"]
let review_nodes = map(
  ((|id| => agents.agent<Task, Review>(id, reviewer_config)): fn(String) -> Node<Task, Result<AgentError, Review>>),
  review_ids,
)
let parallel_reviews = sequence(review_nodes)

// A reusable workflow is an ordinary function returning one Node boundary.
// The primitive id is separate from repository-specific reusable config.
let development_workflow: fn(String, DevelopmentConfig) -> Node<Task, Result<AgentError, Review>> = |id, config| => {
  let task = identity<Task>(str(id, ".task"))

  let worktree = create(str(id, ".worktree"), CreateSpec {
    repository: get(config, "repository"),
    path: get(config, "worktree"),
    branch: get(config, "branch"),
    base: get(config, "base")
  })
  let worktree_after_task = `*>`(identity<Task>(str(id, ".worktree-trigger")), worktree)
  let implementation_input: Node<Task, (Task, Worktree)> = `&&&`(task, worktree_after_task)

  let implementer = agents.agent<(Task, Worktree), Implementation>(str(id, ".implementer"), agents.AgentConfig {
    model: agents.standard,
    system: "Implement the task in its worktree.",
    tools: general_tools,
    tool_approval_policy: no_tool_approval_policy(),
    max_corrections: 2
  })
  let implemented: Node<Task, Result<AgentError, Implementation>> = `>>>`(implementation_input, implementer)

  // Pair each successful implementation with its bounded deterministic build.
  let build = script(str(id, ".build"), ShellScriptParams {
    script: get(config, "build"),
    cwd: get(config, "worktree"),
    timeout: timeout_ms(120000)
  })
  let implementation = identity<Implementation>(str(id, ".implementation"))
  let build_after_implementation = `*>`(identity<Implementation>(str(id, ".build-trigger")), build)
  let implementation_and_build = `&&&`(implementation, build_after_implementation)
  let built: Node<Task, Result<AgentError, (Implementation, ProcessResult)>> = result_map(implemented, implementation_and_build)

  let reviewer = agents.agent<(Task, Result<AgentError, (Implementation, ProcessResult)>), Review>(str(id, ".reviewer"), reviewer_config)

  // identity preserves original intent; &&& sends the same task through both
  // branches; the product emits only after both task and implementation result exist.
  let retained_task = identity<Task>(str(id, ".retained-task"))
  let review_input = `&&&`(retained_task, built)
  let review_result = `>>>`(review_input, reviewer)

  // map_error transforms only Error. Identity makes the channel explicit here;
  // a real workflow can substitute a domain-specific error normalizer.
  let same_error = identity<AgentError>(str(id, ".same-error"))
  node_named(id, map_error(review_result, same_error))
}

let development_task = source("development-task", Task {
  prompt: "Implement and review the requested repository change."
})
let development = development_workflow("development", DevelopmentConfig {
  repository: ".",
  worktree: "tmp/mag-book-worktree",
  branch: "mag-book-work",
  base: "main",
  build: "cargo build"
})
let reviewed = `>>>`(development_task, development)

// >=> binds Result-producing nodes: Error passes through unchanged and only Ok
// enters the continuation. choose branches over nominal Either and repacks it.
let decide = agents.agent<Review, Either<Approved, NeedChanges>>("decide", agents.AgentConfig {
  model: agents.standard,
  system: "Classify the review.",
  tools: read_only_tools,
  tool_approval_policy: no_tool_approval_policy(),
  max_corrections: 2
})
let decided = `>=>`(reviewed, decide)
let approved = identity<Approved>("approved")
let changes = identity<NeedChanges>("need-changes")
let branched = result_map(decided, choose("decision", approved, changes))

// Runtime cardinality is different from sequence's compile-time List. The
// planner's selected output is DynamicList<Followup>. traverse applies one
// ordinary typed worker node to every occurrence and preserves completion.
let planner = agents.agent<Either<Approved, NeedChanges>, DynamicList<Followup>>("planner", agents.AgentConfig {
  model: agents.standard,
  system: "Return ordered follow-up investigations.",
  tools: read_only_tools,
  tool_approval_policy: no_tool_approval_policy(),
  max_corrections: 2
})
let planned = `>=>`(branched, planner)

let followup_worker = agents.agent<Followup, Finding>("followup-worker", agents.AgentConfig {
  model: agents.standard,
  system: "Consume the typed Followup input, perform that investigation, and return its Finding.",
  tools: read_only_tools,
  tool_approval_policy: no_tool_approval_policy(),
  max_corrections: 2
})
let workers = traverse("followups", followup_worker)
let investigated = `>=>`(planned, lift<DynamicList<Followup>, AgentError, DynamicList<Result<AgentError, Finding>>>("workers-result", workers))

// context activates once after explicit completion and supplies the ordered
// results to one integrating provider turn, including for an empty collection.
let result_context = context<Result<AgentError, Finding>>("followup-context")
let integrator = agents.agent<ProviderInput, FinalSummary>("integrator", agents.AgentConfig {
  model: agents.standard,
  system: "Integrate the ordered findings.",
  tools: read_only_tools,
  tool_approval_policy: no_tool_approval_policy(),
  max_corrections: 2
})
let production = `>=>`(investigated, `>>>`(result_context, integrator))

// sequence shares Unit across fixed checks and preserves their order. Binary <*
// waits for those checks but retains the summary; it is not an applicative list.
let build_check = script("verification.build", ShellScriptParams {script: "cargo build", cwd: ".", timeout: timeout_ms(120000)})
let test_check = script("verification.test", ShellScriptParams {script: "cargo test", cwd: ".", timeout: timeout_ms(120000)})
let fixed_checks = sequence([build_check, test_check])
let retain_summary = `<*`(identity<FinalSummary>("verification.summary"), fixed_checks)
let verified = result_map(production, retain_summary)

compile_graph(verified)
```

`Node<I, O>` is the reusable boundary. `>>>` feeds ordinary output to input;
`*>` runs a `Unit`-input node after the left and keeps the right result; binary
`<*` also waits for the right but keeps the left result. `&&&` sends one input
to both branches and joins their outputs; `***` maps two nodes over a product;
`+++` maps them over nominal `Either`. These symbolic names use ordinary
binary call syntax above; MAG infix application is reserved for curried
functions. They, `node_named`, `choose`, and `sequence` all return nodes.

`sequence(nodes)` accepts a compile-time `List<Node<I, O>>`. Every child gets
the same `I`, and the output is an ordered `List<O>`. `DynamicList<T>` instead
records runtime-discovered indexed occurrences and explicit completion.
`traverse(id, worker)` lifts an ordinary `Node<I, O>` into a
`Node<DynamicList<I>, DynamicList<O>>`; `context<T>(id)` consumes the completed
ordered collection once.

Agents return `Result<AgentError, O>`. `result_map` transforms only `Ok`,
`map_error` transforms only `Error`, and `>=>` chains two Result-producing
nodes without extra IDs at the call site. Deterministic nodes enter the same
channel through `lift<I, E, O>(id, node)`; `_` may fill inferable type holes.

Logical paths and runtime actor IDs are different identities. Actor IDs are
opaque strings: never split them on dots to infer hierarchy. `rename` changes
one displayed path segment, while `node_named` creates an expandable hierarchy
boundary. Every complete logical path must be unique within one run.
