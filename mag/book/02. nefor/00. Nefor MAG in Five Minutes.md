# Nefor MAG in Five Minutes

This guide assumes [MAG in Five Minutes](<../01. core/00. MAG in Five Minutes.md>).
It starts with one node and builds progressively larger programs: a typed
development cycle and then a dynamically sized swarm. Each section introduces
one Nefor concept; the representation Nefor executes is left until the end.
The same values can be composed directly for a one-off workflow or hidden
behind ordinary functions when repetition and scale make that useful.

```lisp
(require "nefor.actors")
(require "nefor.artifact")
(require "nefor.contracts")
(require "nefor.dynamic")
(require "nefor.graph")
(require "nefor.shell")
(require "nefor.worktree")

;; MAG block bindings are peers, as the core guide explains. A few small helper
;; implementations therefore live in the final "under the hood" section even
;; though the readable program uses them earlier.

;; ------------------------------------------------------------
;; 1. A node is one typed piece of work
;; ------------------------------------------------------------

;; Node I O means: give this piece of work an I and it eventually produces an
;; O. Merely constructing a node is pure MAG data manipulation; nothing runs.
;; Semantically, Nefor nodes are reasoners; structurally, Node is ordinary data
;; defined by Nefor's MAG libraries. MAG itself knows neither concept. This
;; deterministic node accepts Unit or Text and returns ProcessResult.
(let repository ".")
(let worktree-path "tmp/mag-book-sdlc")
(let build-command "cargo build")
(let build
  (nefor.shell.script "build"
    (as nefor.shell.ShellScriptParams
      {:script build-command
       :cwd worktree-path
       :timeout (nefor.contracts.no-timeout)})))

;; Every node exposes typed input and output ports. Ports are connection points,
;; not imperative handles: sending a value to an input is described in the
;; graph artifact and happens only when Nefor executes that artifact.
(let build-input-port (get build "input"))
(let build-output-port (get build "output"))

;; ------------------------------------------------------------
;; 2. A graph connects nodes
;; ------------------------------------------------------------

;; A source supplies the command's first value and an output marks the value
;; returned by the run. An edge connects one node's output to the next node's
;; input. nefor.artifact.compile validates this complete graph and returns an
;; Artifact, the same ordinary MAG result concept used in the core guide.
(let command-start
  (nefor.graph.source "command-start"
    (type-tag (| Unit nefor.contracts.Text))
    (as (| Unit nefor.contracts.Text)
      (as nefor.contracts.Text {:content "run"}))))
(let command-result-node
  (nefor.graph.output "command-result"
    (type-tag nefor.contracts.ProcessResult)))
(let command-program
  (fn [] -> Artifact
    (nefor.artifact.compile
      (fn [[graph nefor.graph.Graph]] -> nefor.graph.Graph
        (nefor.graph.add-edges graph
          [(nefor.graph.edge command-start build)
           (nefor.graph.edge build command-result-node)])))))

;; Calling `(command-program)` as the source file's final expression is a
;; complete single-command program and makes Nefor run exactly that graph.

;; ------------------------------------------------------------
;; 3. An agent is a node too
;; ------------------------------------------------------------

;; Agents have the same Node I O boundary as deterministic work. `one-agent`
;; is this program's generic Node-producing function: it chooses the shared
;; model configuration while its arguments choose types, tools, and policy.
;; The input type also determines the private runtime entry protocol; authors
;; do not name actor wires. Its implementation is shown in the final section.

;; Model is deliberately owned by this program's configuration, not Nefor.
;; A work configuration could define a different finite sum with internal
;; providers and models. Exhaustive matching makes an unresolved model choice a
;; compile-time error rather than a runtime string lookup.
(type Fast {})
(type Standard {})
(type Deep {})
(type Model (| Fast Standard Deep))
(let standard-model (as Model (as Standard {})))

(let hello-task
  (nefor.actors.task-source "hello-task"
    "Explain why typed graph composition is useful."))
(let explainer
  (one-agent "explainer"
    "Answer the supplied task concisely."
    (type-tag nefor.contracts.Task)
    (type-tag nefor.contracts.TextAnswer)
    nefor.actors.read-only-tools
    (nefor.contracts.no-da-policy)))
(let explanation-node
  (nefor.graph.output "explanation"
    (type-tag (| nefor.contracts.TextAnswer nefor.contracts.AgentError))))
(let agent-program
  (fn [] -> Artifact
    (nefor.artifact.compile
      (fn [[graph nefor.graph.Graph]] -> nefor.graph.Graph
        (nefor.graph.add-edges graph
          [(nefor.graph.edge hello-task explainer)
           (nefor.graph.edge explainer explanation-node)])))))

;; Calling `(agent-program)` is the complete single-agent equivalent. Adding
;; more agents or deterministic steps does not change the model: create nodes,
;; connect compatible ports, and return the resulting artifact.

;; ------------------------------------------------------------
;; 4. Project types define a development workflow
;; ------------------------------------------------------------

;; The workflow owns these types. Nefor supplies generic agents, commands,
;; worktrees, graphs, and rules; it does not prescribe an SDLC.
(type BuildPassed {:stdout String})
(type BuildFailed
  {:stdout String
   :stderr String
   :termination nefor.contracts.ProcessTermination})
(type BuildFeedback (| BuildPassed BuildFailed))
(type NeedChanges {:feedback String})
(type Approved {:summary String})
(type BuilderInput
  (| nefor.contracts.ProviderInput BuildFailed NeedChanges))
(type ReviewDecision (| Approved NeedChanges))
(type DevelopmentComplete {:summary String :worktree String})

(let builder-policy
  (nefor.contracts.da-policy
    (assoc (as (Map String String) {}) build-command "deny")))

;; A worktree is another node: Unit creates one Worktree value. The task and
;; worktree outputs join at builder-context, which serializes their complete
;; product into the ProviderInput expected by the builder.
(let worktree
  (nefor.worktree.create "development-worktree"
    (as nefor.worktree.CreateSpec
      {:repository repository
       :path worktree-path
       :branch "mag-book-sdlc"
       :base "main"})))
(let builder-context
  (provider-context "builder-context"
    (type-tag (+ nefor.contracts.Task nefor.worktree.Worktree))))
(let builder
  (one-agent "builder"
    (str
      "Implement the supplied task in the supplied worktree. Do not run "
      (str build-command
        "; the workflow runs it deterministically and returns typed failures."))
    (type-tag BuilderInput)
    (type-tag nefor.contracts.TextAnswer)
    nefor.actors.general-tools
    builder-policy))
(let reviewer
  (one-agent "reviewer"
    "Review the completed work and return Approved or NeedChanges."
    (type-tag BuildPassed)
    (type-tag ReviewDecision)
    nefor.actors.read-only-tools
    (nefor.contracts.no-da-policy)))
(let development-result-node
  (nefor.graph.output "development-result" (type-tag DevelopmentComplete)))

;; ------------------------------------------------------------
;; 5. Resident rules make runtime decisions
;; ------------------------------------------------------------

;; Static edges are enough when every value always has the same destination.
;; A resident rule is used when a runtime value decides what happens next. It
;; observes a port and calls a named pure MAG function. That function returns
;; an Artifact containing the graph change Nefor should apply atomically.

;; The builder's answer activates the deterministic build. The answer becomes
;; Text only to satisfy the command's Unit | Text input; the command itself is
;; the already-bound build-command and cannot be improvised by the builder.
(let run-build
  (fn [[answer nefor.contracts.TextAnswer]] -> Artifact
    (emit build-input-port
      (as (| Unit nefor.contracts.Text)
        (as nefor.contracts.Text {:content answer})))))

;; ProcessResult is ordinary data. Its termination is a typed sum: a process
;; either exits with a code or is terminated by a signal. This local mapping
;; turns those generic facts into the exact variants this SDLC needs. `match`
;; is exhaustive, so adding another termination variant would require this
;; workflow to decide explicitly how that new case should be handled.
;; This is the usual functional "errors as values" pattern: build failure is
;; business data here, so the workflow branches on it instead of throwing.
(let build-failure
  (fn [[result nefor.contracts.ProcessResult]
       [termination nefor.contracts.ProcessTermination]] -> BuildFeedback
    (as BuildFeedback
      (as BuildFailed
        {:stdout (get result "stdout")
         :stderr (get result "stderr")
         :termination termination}))))
(let classify-build
  (fn [[result nefor.contracts.ProcessResult]] -> BuildFeedback
    (match (get result "termination")
      [nefor.contracts.ProcessExited exited
        (if (= (get exited "code") 0)
          (as BuildFeedback
            (as BuildPassed {:stdout (get result "stdout")}))
          (build-failure result
            (as nefor.contracts.ProcessTermination exited)))]
      [nefor.contracts.ProcessSignaled signaled
        (build-failure result
          (as nefor.contracts.ProcessTermination signaled))])))

;; Success goes to the reviewer; failure returns to the same builder input.
;; The BuildFeedback constructor is retained by MAG, so no string tag or cast
;; is needed to discover which payload this branch received.
(let route-build-result
  (fn [[result nefor.contracts.ProcessResult]] -> Artifact
    (match (classify-build result)
      [BuildPassed passed
        (emit (get reviewer "input") passed)]
      [BuildFailed failed
        (emit (get builder "input") (as BuilderInput failed))])))

;; Review feedback takes the other feedback arm. Approval produces the typed
;; result consumed by whatever larger workflow uses this development cycle.
(let revise
  (fn [[change NeedChanges]] -> Artifact
    (emit (get builder "input") (as BuilderInput change))))
(let finish-development
  (fn [[approval Approved]] -> Artifact
    (emit (get development-result-node "input")
      (as DevelopmentComplete
        {:summary (get approval "summary") :worktree worktree-path}))))

;; ------------------------------------------------------------
;; 6. A complete workflow is one reusable value
;; ------------------------------------------------------------

;; This program represents a composed reasoner by the change that installs it,
;; the resident rules that continue it, and its typed public boundary. The
;; representation is an ordinary task-local MAG type, not a MAG language form.
(type ResidentWorkflow [I O]
  {:change nefor.graph.Delta
   :rules (List nefor.graph.Rule)
   :input-port (nefor.graph.Port I)
   :output-port (nefor.graph.Port O)})

(let sdlc
  (fn [[task String]] -> (ResidentWorkflow Unit DevelopmentComplete)
    (let task-source (nefor.actors.task-source "development-task" task))

    ;; Node types differ, but every node lowers to the same Delta type. Once
    ;; lowered, an ordinary fold can combine the heterogeneous constellation.
    (let with-result
      (fold nefor.graph.merge-delta empty-change
        [(nefor.graph.node-delta task-source)
         (nefor.graph.node-delta worktree)
         (nefor.graph.node-delta builder-context)
         (nefor.graph.node-delta builder)
         (nefor.graph.node-delta build)
         (nefor.graph.node-delta reviewer)
         (nefor.graph.node-delta development-result-node)]))

    ;; Then connect the values which always have one destination. Both task and
    ;; worktree feed the product input; the adapter waits for both occurrences.
    (let connected
      (connect-all with-result
        [(>>> task-source builder-context)
         (>>> worktree builder-context)
         (>>> builder-context builder)]))

    ;; The initial Unit starts worktree creation. Everything after the builder
    ;; is selected by the resident rules below.
    (let started
      (nefor.graph.delta-message-front connected (get worktree "input") nil))

    (as (ResidentWorkflow Unit DevelopmentComplete)
      {:change started
       :rules
       [(nefor.graph.rule "run-build"
          (nefor.actors.result-arm builder
            (type-tag nefor.contracts.TextAnswer))
          "run-build")
        (nefor.graph.rule "route-build-result" build-output-port
          "route-build-result")
        (nefor.graph.rule "revise"
          (nefor.actors.result-arm reviewer (type-tag NeedChanges))
          "revise")
        (nefor.graph.rule "finish-development"
          (nefor.actors.result-arm reviewer (type-tag Approved))
          "finish-development")]
       :input-port (get worktree "input")
       :output-port (get development-result-node "output")})))

;; The complete cycle is now one typed value. Code composing a larger workflow
;; no longer needs to know that it contains a worktree, two agents, a command,
;; feedback branches, or four resident rules.
(let development
  (sdlc "Implement and review the requested repository change."))

;; ------------------------------------------------------------
;; 7. Runtime values can determine the graph's size
;; ------------------------------------------------------------

;; A later agent derives follow-up investigations from the completed work. The
;; number of tasks is known only when that agent answers, so expand-swarm makes
;; exactly one worker node per returned item.
(type SwarmTask {:title String :instructions String})
(type WorkerResult {:title String :finding String})
(type SwarmSummary {:content String})
(type IndexedTask {:index Int :value SwarmTask})

(let planner
  (one-agent "planner"
    "Derive the independent follow-up investigations from the completed work."
    (type-tag DevelopmentComplete)
    (type-tag (List SwarmTask))
    nefor.actors.read-only-tools
    (nefor.contracts.no-da-policy)))
(let collected-prompt-node
  (nefor.dynamic.collected-prompt "swarm-results"
    (type-tag (| WorkerResult nefor.contracts.AgentError))))
(let integrator
  (one-agent "integrator"
    "Integrate the dynamically produced worker findings."
    (type-tag nefor.contracts.ProviderInput)
    (type-tag SwarmSummary)
    nefor.actors.read-only-tools
    (nefor.contracts.no-da-policy)))
(let final-result-node
  (nefor.graph.output "result"
    (type-tag (| SwarmSummary nefor.contracts.AgentError))))

(let indexed-task
  (fn [[index Int] [task SwarmTask]] -> IndexedTask
    (as IndexedTask {:index index :value task})))
(let worker-id
  (fn [[entry IndexedTask]] -> String
    (str "swarm.worker." (get entry "index"))))
(let make-worker
  (fn [[entry IndexedTask]]
    -> (nefor.graph.Node SwarmTask
         (| WorkerResult nefor.contracts.AgentError))
    (let task (get entry "value"))
    (one-agent (worker-id entry)
      (get task "instructions")
      (type-tag SwarmTask)
      (type-tag WorkerResult)
      nefor.actors.read-only-tools
      (nefor.contracts.no-da-policy))))

;; Each fold step adds one independently constructed node and sends that worker
;; its own typed task. collect-all owns the result routes separately.
(let add-worker
  (fn [[change nefor.graph.Delta]
       [entry IndexedTask]] -> nefor.graph.Delta
    (let worker (make-worker entry))
    (let with-worker (include change worker))
    (nefor.graph.delta-message-front with-worker
      (get worker "input") (get entry "value"))))

(let expand-swarm
  (fn [[tasks (List SwarmTask)]] -> Artifact
    (let indexed (indexed-map indexed-task tasks))
    (let workers (map make-worker indexed))
    (let outputs
      (map
        (fn [[worker (nefor.graph.Node SwarmTask
                       (| WorkerResult nefor.contracts.AgentError))]]
          -> (nefor.graph.Port (| WorkerResult nefor.contracts.AgentError))
          (get worker "output"))
        workers))
    ;; The output list follows outputs exactly, regardless of arrival order.
    ;; With no workers, collect-all is the list identity and produces [].
    (let collection
      (nefor.dynamic.collect-all "swarm.collector" outputs
        (type-tag (| WorkerResult nefor.contracts.AgentError))))
    (let change
      (fold
        add-worker
        (get collection "change")
        indexed))
    (nefor.artifact.delta
      (connect change
        (get collection "output")
        (get collected-prompt-node "input")))))

;; ------------------------------------------------------------
;; 8. Compose the production workflow
;; ------------------------------------------------------------

;; At this level the entire SDLC is consumed through the same typed boundary as
;; an individual node. Its implementation is no longer part of the composition.
(let with-final-result
  (fold nefor.graph.merge-delta (get development "change")
    [(nefor.graph.node-delta planner)
     (nefor.graph.node-delta collected-prompt-node)
     (nefor.graph.node-delta integrator)
     (nefor.graph.node-delta final-result-node)]))
(let production-change
  (connect-all with-final-result
    [(nefor.graph.stored-route
       (get development "output-port") (get planner "input"))
     (>>> collected-prompt-node integrator)
     (>>> integrator final-result-node)]))
(let all-rules
  (concat
    (get development "rules")
    [(nefor.graph.rule "expand-swarm"
       (nefor.actors.result-arm planner (type-tag (List SwarmTask)))
       "expand-swarm")]))

;; ------------------------------------------------------------
;; 9. Under the hood: changes and lowering
;; ------------------------------------------------------------

;; The public model above is sufficient for authoring: nodes, connections,
;; initial values, and rules. The remaining helpers reveal its representation.
;; A Delta is immutable data containing actors, routes, messages, and kills.
(let empty-change
  (nefor.graph.delta
    (as (List nefor.graph.Actor) [])
    (as (List nefor.graph.StoredRoute) [])
    (as (List nefor.graph.Message) [])
    (as (List String) [])))

;; Including a node adds the low-level data hidden behind its typed boundary.
(let include
  (fn [I O] [[change nefor.graph.Delta] [value (nefor.graph.Node I O)]]
    -> nefor.graph.Delta
    (nefor.graph.merge-delta change (nefor.graph.node-delta value))))

;; >>> forgets the internal types of two composable boundaries and returns one
;; StoredRoute. A ResidentWorkflow deliberately remains a different abstraction
;; and exposes its boundary ports directly.
(let >>>
  (fn [A B C D] [[from (nefor.graph.Node A B)]
                 [to (nefor.graph.Node C D)]] -> nefor.graph.StoredRoute
    (nefor.graph.stored-route (get from "output") (get to "input"))))

(let connect-all
  (fn [[change nefor.graph.Delta]
       [routes (List nefor.graph.StoredRoute)]] -> nefor.graph.Delta
    (nefor.graph.merge-delta change
      (nefor.graph.delta
        (as (List nefor.graph.Actor) [])
        routes
        (as (List nefor.graph.Message) [])
        (as (List String) [])))))

;; connect is deliberately heterogeneous: lowering checks how the source type
;; inhabits the destination product or union and assigns the corresponding
;; product position. Equal types are simply the common case.
(let connect
  (fn [A B] [[change nefor.graph.Delta]
             [from (nefor.graph.Port A)] [to (nefor.graph.Port B)]]
    -> nefor.graph.Delta
    (connect-all change [(nefor.graph.stored-route from to)])))

(let emit
  (fn [T] [[to (nefor.graph.Port T)] [value T]] -> Artifact
    (nefor.artifact.delta
      (nefor.graph.delta-message empty-change to value))))
(let message-change
  (fn [[value nefor.graph.Message]] -> nefor.graph.Delta
    (nefor.graph.delta
      (as (List nefor.graph.Actor) [])
      (as (List nefor.graph.StoredRoute) [])
      [value]
      (as (List String) []))))

;; The config-owned resolver turns this program's Model sum into the concrete
;; runtime values Nefor understands. Neither MAG nor Nefor has a built-in
;; concept of profiles.
(let resolve-model
  (fn [[model Model]] -> nefor.actors.ResolvedModel
    (match model
      [Fast value
        (as nefor.actors.ResolvedModel
          {:provider "chatgpt" :model "gpt-5.6-luna"
           :reasoning-effort "low"})]
      [Standard value
        (as nefor.actors.ResolvedModel
          {:provider "chatgpt" :model "gpt-5.6-sol"
           :reasoning-effort "medium"})]
      [Deep value
        (as nefor.actors.ResolvedModel
          {:provider "chatgpt" :model "gpt-5.6-sol"
           :reasoning-effort "high"})])))

;; one-agent is an ordinary function around the generic Nefor constructor. It
;; fixes this workflow's model choice and preserves the typed node boundary.
(let one-agent
  (fn [I O] [[id String] [system String]
             [input-type (TypeTag I)] [output-type (TypeTag O)]
             [tools (List String)] [policy nefor.contracts.DaPolicy]]
    -> (nefor.graph.Node I (| O nefor.contracts.AgentError))
    (nefor.actors.agent resolve-model
      (as (nefor.actors.AgentConfig Model)
        {:id id
         :model standard-model
         :system system
         :tools tools
         :da-policy policy
         :max-corrections 2})
      input-type output-type)))

;; builder-context is the only task-local node whose public library constructor
;; did not already exist. Internally a Node may contain several actors and
;; routes; callers still see only Node I O. This adapter contains one actor.
(let provider-context
  (fn [T] [[id String] [input-type (TypeTag T)]]
    -> (nefor.graph.Node T nefor.contracts.ProviderInput)
    (let input-port
      (nefor.graph.port id input-type "nefor.agent.Input"))
    (let output-port
      (nefor.graph.port id (type-tag nefor.contracts.ProviderInput)
        "generic-provider.ProviderOut"))
    (nefor.graph.node id "ordinary"
      [(nefor.graph.actor id nefor.actors.adapter-factory
         [(type-evidence input-type)]
         (as nefor.actors.AdapterParams
           {:seed "provider-in" :schema (type-schema input-type)})
         (nefor.graph.store-port input-port)
         [(nefor.graph.store-port output-port)])]
      (as (List nefor.graph.StoredRoute) [])
      (as (List nefor.graph.Message) [])
      input-port output-port)))

;; Lowering is the final implementation boundary. It expands the authored
;; hierarchy into the actors, routes, initial messages, resident rules, types,
;; and result boundary understood by Nefor's runtime. MAG still executes none
;; of that work; it serializes this immutable value as the program's artifact.
(artifact
  (nefor.graph.lower-resident
    production-change all-rules (get final-result-node "output")))
```

The first two functions, `command-program` and `agent-program`, show the
smallest runnable deterministic and agent graphs. The final artifact uses the
same node and connection model at production scale: the SDLC has become one
typed workflow value, and a runtime rule expands the later swarm only when its
actual task list exists.
